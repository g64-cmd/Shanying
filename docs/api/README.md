# API 设计与评审

业务接口尚未冻结。首个业务切片建立 `/api/v1` 路径及完整 schema 后，才开始生成三端类型。

统一设计约束：ID 使用字符串避免 JavaScript 精度损失；时间使用 UTC RFC3339；明确必填、可空与缺省；列表使用不透明 cursor 和明确的结束标志；错误响应携带稳定业务码、可读消息及 request ID。HTTP 状态必须与成功/认证/授权/限流/服务失败语义一致。

每条接口的完成条件包括：请求和响应 schema、鉴权与对象权限、成功/失败样例、幂等及重试规则、分页稳定性、兼容性说明，以及 Web/Android 消费结果。新增字段保持向后兼容；删除、重命名或枚举收紧必须有版本/迁移方案。

| 能力 | Android 必须提前验证的点 | 状态 |
| --- | --- | --- |
| 认证 | 刷新并发、撤销、过期、设备安全存储 | 待设计 |
| Feed/详情 | cursor 重试、结束、删除内容、媒体 URL 过期 | 待设计 |
| 上传/发布 | 进度、取消、弱网恢复、上传确认和处理失败 | 待设计 |
| 点赞/关注 | 设置目标状态、重复提交和状态回读 | 待设计 |
| 评论/资料 | 分页、长度边界、权限、空值及删除 | 待设计 |

所有“待设计”项在对应切片合并前解决，而非等 Android 界面开发结束再补协议。
