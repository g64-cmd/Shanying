# Proposal

## Why

平台范围已确认，但尚无可执行的账号契约、表设计或权限并发规则。先将后端工程底座和账号权限细化为一个可验收切片，避免三端在编码中分别决定身份、隐私与会话行为。

## What Changes

- 确定 Go/Hertz 单机模块化单体的目录、依赖、事务、错误、日志、配置和测试规则。
- 将邮箱验证注册、登录、轮换刷新、找回/修改密码、会话撤销、资料与关系管理定义为 OpenAPI。
- 设计 PostgreSQL 表、约束、索引、锁顺序与账号/凭证/关系状态转换。
- 细化完整屏蔽：拉黑原子删除双向关注/申请，阻止作品访问和重新关注，解黑不恢复旧关系（2026-10-26 用户确认）。
- 给出测试矩阵及后续切片联合设计门槛；本次不生成业务代码或执行数据库迁移。

## Capabilities

### New Capabilities
- `backend-foundation`：健康探针、错误/配置/日志和可靠邮件投递的外部约束。
- `account-privacy`：沿用平台规划的同名能力，新增首切片的精确认证、会话、关系及授权行为。

### Modified Capabilities

无已归档主规格。本 change 与 define-shanying-platform/specs/account-privacy 共同构成该能力；此处仅新增不同名称的细化要求，不复制覆盖原要求。共享主规格同步时保留两者并集，不以同步文档冒充实现验收。

## Impact

新增 docs/backend/ 下工程、数据、状态、测试文档以及 docs/api/account-access.md；补全唯一根契约 contracts/openapi.yaml。关联平台路线的 1.1、1.4、2.1–2.3；1.2/1.3 的完整客户端工程另做，本切片要求 TS/Kotlin 契约消费证据。没有视频/私聊/商家管理 HTTP 实现，不做注销、邮箱更换、短信、第三方登录、真实订单资金。权限只提供明确的模块接口，不预建所有未来业务表。
