# Spec Delta

## Purpose

确保闪映服务端、Web 与 Android 使用一致且可验证的外部协议，在接口设计阶段暴露移动端认证、弱网恢复、上传及分页需求，避免在客户端开发末期通过不兼容修改返工。

## ADDED Requirements

### Requirement: 统一协议来源
系统 SHALL 为三端维护同一份版本化 API 契约，明确字段、授权、错误和样例；新增业务接口不得仅通过端侧私有类型定义。

#### Scenario: 新增接口
- **WHEN** 任一端提出新的业务接口
- **THEN** 接口在实现合入前具有共享契约及三端消费评审记录

### Requirement: Android 提前消费
系统 SHALL 在每个业务切片交付时验证 Android 对请求、响应和错误样例的消费能力，即使 Android 界面仍未完成。

#### Scenario: Web 先完成界面
- **WHEN** Web 切片已完成而 Android 界面尚未完成
- **THEN** 发布验收仍要求 Kotlin 客户端构建和契约样例测试证据

### Requirement: 恢复语义明确
系统 SHALL 在相关接口交付前定义认证过期、弱网重试、游标结束、重复写入、上传未完成与媒体失效的可观察结果。

#### Scenario: 点赞请求重试
- **WHEN** 客户端因响应丢失而重复提交同一个目标点赞状态
- **THEN** 最终只存在一份关系且可查询确认状态

#### Scenario: 上传尚未确认
- **WHEN** 客户端上传中断或服务端尚未确认处理就绪
- **THEN** 客户端可查询明确状态，视频不会作为可播放内容出现在公开流

### Requirement: 兼容性发布门槛
系统 SHALL 在发布前检查契约兼容性和三端消费结果；未完成验证不得视为通过。

#### Scenario: 删除已使用字段
- **WHEN** 变更删除一个客户端仍在使用的字段
- **THEN** 发布被阻止，直到提供明确迁移方案并完成受影响客户端验证
